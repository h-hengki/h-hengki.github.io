# 05. 사용자별 DB 접근 제어 (client scope 기반)

목표: API 사용자(클라이언트)마다 접근 가능한 dbId를 제한한다.
예) 신규 사용자 X는 `smsp`만 조회 가능, `api-test`는 전체 조회 가능.

원리:
1. Keycloak **client scope** = DB별 권한 딱지 (`db-smsp`, `db-sccm`, ...)
2. 클라이언트에 필요한 scope만 부여 → 토큰의 `scope` 클레임에 반영됨
3. APISIX 라우트를 **DB별로 분리**하고, 각 라우트에 `required_scopes` 지정
   → 해당 scope 없는 토큰은 403 Forbidden

> `required_scopes`는 APISIX가 Keycloak introspection으로 토큰을 검사할 때 동작한다.
> 현재 라우트 구성(bearer_only + discovery, use_jwks 미사용)이 introspection 방식이므로 그대로 적용 가능.

## 1단계. Keycloak에 DB별 client scope 생성

콘솔(`aigateway` realm) → **Client scopes** → **Create client scope**. DB마다 반복:

| 항목 | 값 |
|---|---|
| Name | `db-smsp` (DB별로 `db-<dbId>` 규칙) |
| Type | None |
| Protocol | OpenID Connect |
| **Include in token scope** | **On** (필수 — 꺼져 있으면 토큰 scope에 안 들어감) |

생성 대상 (11개): `db-sampledb`, `db-smsp`, `db-sccm`, `db-lmsp`, `db-lccm`, `db-slbm`,
`db-ssbm`, `db-ssbmfce`, `db-bica`, `db-sicb`, `db-sici`

## 2단계. 클라이언트에 scope 부여

**Clients** → 대상 클라이언트 → **Client scopes** 탭 → **Add client scope**:

- 신규 사용자 X (smsp만): `db-smsp` 선택 → **Add > Default**
- `api-test` (전체): `db-*` 11개 모두 선택 → **Add > Default**

> "Default"로 추가해야 client_credentials 토큰에 자동 포함된다 (Optional은 요청 시에만).

**토큰 확인** — scope 클레임에 딱지가 들어있는지:

```bash
curl -s -X POST "http://172.31.209.71:8180/realms/aigateway/protocol/openid-connect/token" \
  -d "grant_type=client_credentials" -d "client_id=<클라이언트>" -d "client_secret=<시크릿>" \
  | python3 -c "import sys,json,base64; t=json.load(sys.stdin)['access_token'].split('.')[1]; print(json.loads(base64.urlsafe_b64decode(t+'=='))['scope'])"
# 예상 출력: profile email db-smsp
```

## 3단계. APISIX 라우트를 DB별로 분리

기존 공용 라우트(`/api/*`) 대신 DB별 라우트 11개를 만든다. 각 라우트는
`required_scopes: ["db-<dbId>"]`로 해당 딱지를 강제한다.

```bash
cd ~/gateway && source .env
CLIENT_SECRET="<api-test의 시크릿>"   # 라우트의 introspection용 자격증명

for db in sampledb smsp sccm lmsp lccm slbm ssbm ssbmfce bica sicb sici; do
curl -s -X PUT "http://127.0.0.1:9180/apisix/admin/routes/ai-data-${db}" \
  -H "X-API-KEY: ${APISIX_ADMIN_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ai-data-'"${db}"'",
    "uri": "/api/'"${db}"'/*",
    "methods": ["GET"],
    "plugins": {
      "openid-connect": {
        "client_id": "api-test",
        "client_secret": "'"${CLIENT_SECRET}"'",
        "discovery": "http://172.31.209.71:8180/realms/aigateway/.well-known/openid-configuration",
        "bearer_only": true,
        "realm": "aigateway",
        "required_scopes": ["db-'"${db}"'"]
      },
      "proxy-rewrite": {
        "regex_uri": ["^/api/(.*)", "/v1/rdbms/$1"]
      }
    },
    "upstream": { "type": "roundrobin", "nodes": { "db2rest:8080": 1 } }
  }'
echo " => ${db}"
done

# 기존 공용 라우트 삭제 (이걸 남기면 scope 검사를 우회할 수 있음!)
curl -s -X DELETE "http://127.0.0.1:9180/apisix/admin/routes/ai-data-api" \
  -H "X-API-KEY: ${APISIX_ADMIN_KEY}"
```

> ⚠️ 순서 주의: **2단계에서 api-test 등 기존 사용자에게 scope를 먼저 부여한 뒤** 3단계를
> 실행할 것. 순서가 바뀌면 기존 사용자가 일시적으로 403을 받는다.

## 4단계. 검증

```bash
# 신규 사용자 X 토큰 (db-smsp만 보유)
TOKEN_X=$( ... client_id=<X> ... )

curl -s -o /dev/null -w "%{http_code}\n" "http://172.31.209.71:9080/api/smsp/smsp1010?limit=1" \
  -H "Authorization: Bearer ${TOKEN_X}"     # → 200 (허용)

curl -s -o /dev/null -w "%{http_code}\n" "http://172.31.209.71:9080/api/sccm/anytable" \
  -H "Authorization: Bearer ${TOKEN_X}"     # → 403 (scope 없음 → 차단)

# api-test 토큰 (전체 scope 보유) → 모든 dbId 200
```

## 운영 규칙

- **신규 사용자 발급 절차** = doc/03 2단계(클라이언트 생성) + 이 문서 2단계(필요한 db-* scope 부여).
  라우트는 손댈 필요 없음.
- **권한 변경** = 클라이언트의 Client scopes 탭에서 scope 추가/제거 (즉시 반영, 단 이미 발급된
  토큰은 만료(300초)까지 기존 권한 유지).
- **DB 추가 시** = ① Keycloak에 `db-<신규dbId>` scope 생성 ② 3단계 형식으로 라우트 1개 추가
  ③ 접근할 사용자에게 scope 부여.
- 발급 현황은 doc/03 "발급 현황 관리" 표에 **부여 scope 포함**해서 기록할 것.
