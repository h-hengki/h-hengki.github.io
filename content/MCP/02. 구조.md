# 02. 어디에 무엇을 두나 (핵심 기준표)

이 문서 하나만 봐도 되도록 만들었습니다. 헷갈리면 여기로 돌아오세요.

## 한 줄 규칙

> **나만 쓰면 3층, 팀이 같이 쓰면 2층, 전사가 쓰면 1층.**

## 계층 구조

```
0층  관리자 강제 설정          managed-settings.json          IT 배포. 현재 미사용
1층  전역 (회사 표준)          vntg-standard 플러그인          개발플랫폼팀
     전역 (개인 기본값)        ~/.claude/settings.json         본인 + /vntg-setup-global
2층  프로젝트 (팀 공유)        <repo>/.claude/settings.json    프로젝트 리드, git 커밋
3층  개인 (프로젝트별)         .claude/settings.local.json     본인, git 제외
```

우선순위: **0층 > CLI 옵션 > 3층 > 2층 > 1층**

숫자가 헷갈리기 쉬운데, 요점은 이것입니다.

- **개인 설정이 팀 설정보다 강합니다.** 그래서 팀 공유가 필요한 건 3층에 두면 안 됩니다.
- **팀 설정이 개인 전역 설정보다 강합니다.** 그래서 프로젝트 특성은 2층에서 잡습니다.
- **`permissions.deny` 는 예외입니다.** 모든 층의 deny가 합쳐지고, deny가 allow를 항상 이깁니다.
  즉 금지 규칙은 어느 층에 넣어도 뚫리지 않습니다.

## 무엇을 어디에

| 넣고 싶은 것 | 층 | 정확한 위치 | git |
| --- | --- | --- | --- |
| 전사 코드리뷰 기준, 커밋 규칙 | 1 | `vntg-standard` 플러그인 `skills/` | 이 리포 |
| 전사 공통 MCP (Jira, 사내 위키) | 1 | 플러그인 `.mcp.json` | 이 리포 |
| 시크릿 커밋 방지 같은 가드레일 | 1 | 플러그인 `hooks/hooks.json` | 이 리포 |
| 회사 금지 명령 목록 | 1 | `~/.claude/settings.json` (`/vntg-setup-global`) | 없음 |
| 내가 쓰는 모델, 출력 스타일 | 1 | `~/.claude/settings.json` | 없음 |
| 내 개인 전역 지침 | 1 | `~/.claude/CLAUDE.md` | 없음 |
| 이 프로젝트 빌드/테스트 명령 허용 | 2 | `.claude/settings.json` `permissions.allow` | 커밋 |
| 이 프로젝트 아키텍처, 실행법, 함정 | 2 | `CLAUDE.md` | 커밋 |
| 이 프로젝트 전용 MCP (프로젝트 DB 등) | 2 | `.mcp.json` | 커밋 |
| 이 프로젝트만의 스킬 | 2 | `.claude/skills/<이름>/SKILL.md` | 커밋 |
| 이 프로젝트만의 슬래시 명령 | 2 | `.claude/commands/<이름>.md` | 커밋 |
| 이 프로젝트만의 서브에이전트 | 2 | `.claude/agents/<이름>.md` | 커밋 |
| 팀이 함께 켤 플러그인 | 2 | `.claude/settings.json` `enabledPlugins` | 커밋 |
| 이 프로젝트만의 훅 (커밋 전 포맷 등) | 2 | `.claude/settings.json` `hooks` | 커밋 |
| 내 로컬 경로 접근 허용 | 3 | `.claude/settings.local.json` | 제외 |
| 내 개인 메모, 진행 중 실험 | 3 | `CLAUDE.local.md` | 제외 |

## 자주 하는 실수

| 실수 | 왜 문제인가 | 어떻게 |
| --- | --- | --- |
| 팀 공유 설정을 `settings.local.json` 에 넣음 | git에 안 올라가서 다른 팀원에게 전달 안 됨 | `settings.json` 으로 옮기기 |
| `.mcp.json` 에 DB 비밀번호를 직접 씀 | git에 시크릿이 올라감 | `${VAR}` 로 쓰고 셸 환경변수로 주입 |
| 전사 표준 스킬을 개인이 복사해서 수정 | 표준이 갈라지고 업데이트가 안 됨 | 이 리포에 MR |
| `CLAUDE.md` 에 전사 공통 규칙을 다시 적음 | 중복되고 서로 어긋남 | 프로젝트 고유 내용만 적기 |
| `permissions.allow` 에 배포 명령을 넣음 | 확인 없이 실행될 수 있음 | `ask` 로 옮기기 |
| `.gitignore` 에 `settings.local.json` 누락 | 개인 설정이 팀에 섞임 | `/vntg-init` 가 자동 추가 |
| `.gitignore` 에 `.claude/` 전체를 넣음 | 2층 설정이 아무에게도 공유 안 됨 | 개인 파일 2개만 제외 |
| `Read(//src/**)` 처럼 슬래시 2개 사용 | 파일시스템 루트의 `/src` 를 가리킴 | 프로젝트 기준은 `Read(/src/**)` |
| `enabledPlugins` 만 넣고 설치 안내를 안 함 | 미설치 팀원에게는 아무 일도 안 일어남 | 온보딩에 `/plugin install` 포함 |

## 경로 패턴 규칙 (자주 틀립니다)

| 패턴 | 의미 |
| --- | --- |
| `Read(src/**)` | 이 설정 파일 기준 상대 경로. 어느 깊이에서든 매칭 |
| `Read(/src/**)` | 슬래시 1개. 이 설정 파일이 있는 위치(보통 프로젝트 루트) 기준 |
| `Read(//src/**)` | 슬래시 2개. **파일시스템 루트**의 `/src`. 프로젝트와 무관 |
| `Read(~/.ssh/**)` | 홈 디렉터리 기준 |
| `Bash(npm run test:*)` | `npm run test` 로 시작하는 모든 명령. `:*` 는 **패턴 끝에서만** 유효 |
| `Bash(npm run test)` | 정확히 이 명령만 |

전역 설정에서 다른 프로젝트까지 막으려면 `//` 를 붙입니다. 프로젝트 설정에서는 `/` 를 씁니다.

## CLAUDE.md 는 어디에 몇 개?

읽히는 순서는 넓은 것 → 좁은 것입니다. 모두 합쳐져서 적용됩니다.

| 파일 | 범위 | git |
| --- | --- | --- |
| `~/.claude/CLAUDE.md` | 내 모든 프로젝트 | 없음 |
| `<repo>/CLAUDE.md` | 이 프로젝트, 팀 공유 | 커밋 |
| `<repo>/CLAUDE.local.md` | 이 프로젝트, 나만 | 제외 |
| `<repo>/<하위폴더>/CLAUDE.md` | 그 폴더 작업 시 추가 로드 | 커밋 |

다른 파일을 끌어오려면 `@경로` 를 씁니다. 최대 4단계까지 중첩됩니다.

```markdown
아키텍처는 @docs/architecture.md 참고
API 명세는 @docs/api.md 참고
```
